Identifiers should be clear, consistent, and semantically accurate—avoid redundant renames, ambiguous terminology, and noisy autogenerated fragments.

Apply these rules:

- Destructuring: don’t rename to the same value; use shorthand when names are identical.
  - Prefer: `const { disabled } = t0;`
- Destructuring non-standard keys: quote keys that aren’t valid identifiers.
  - Prefer: `const { 'aria-label': ariaLabel } = t0;`
- API/tool naming: keep terminology consistent with the actual concept, and only vary names to reflect different returned data shapes.
  - If two outputs are conceptually related but structurally different, differentiate them with an explicit suffix (e.g. “..._stack” vs “..._stack_trace”) rather than switching the core term.
- Generated naming: omit generic/no-information fragments (like unnecessary `arg0`) when they don’t add meaning; if your framework/tool knows a special case (e.g. builtin hooks), prefer the shorter label.

Example:
```js
// Destructuring clarity
const { disabled, 'aria-label': ariaLabel } = props;

// Semantic naming (example naming pattern)
// react_get_owners_stack        -> returns owner list
// react_get_owners_stack_trace -> returns raw stack frames
```
