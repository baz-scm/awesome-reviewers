Scoring

VerifyBench (Yan et al., ICLR 2026, arXiv:2505.15801) benchmarks reward verifiers for language models. It scores a verifier by accuracy: the share of labelled items it judges correctly. It reports that accuracy per answer type (numbers, expressions, multiple choice, strings), takes the unweighted average across the types, and adds a Hard split of items that strong models disagree on. The paper does not rank software repositories. This leaderboard borrows its structure:

  • Item: a pair of repository and check kind, where the kind applies to the repository. A kind applies when a recognised tool for it exists for one of the repository's languages or for any language, when the repository runs it anyway, or (for CI workflow linting) when the repository has GitHub Actions workflows.
  • Correct: the repository runs a tool of that kind that the scanner recognises. Tools that are only declared as dependencies, and never run, do not count.
  • Per-method accuracy: the share of correct items within one method, in place of VerifyBench's per-answer-type accuracy. A dash means no kind of that method applies.
  • AVG: the unweighted mean of the per-method accuracies, so a method with many check kinds counts no more than one with few.
  • Hard: accuracy over the check kinds that fewer than {{ l.hard_threshold }}% of the repositories they apply to run, in place of VerifyBench-Hard's disagreement items.
  • Ties: ordered by AVG, then Hard, then the number of kinds run. Repositories equal on all three share a rank.

What it does not measure

  • Only what the scanner reads from CI workflows, hooks, task runners and manifests is counted. A repository that verifies with tools the scanner does not recognise, or in infrastructure outside the repository, scores lower than it should.
  • Code review, finding validation, intent, threat modeling and feedback techniques are not detectable from configuration and are not scored.
  • Running a check is not the same as running it well: the score says nothing about test quality, rule sets or how failures are handled.
