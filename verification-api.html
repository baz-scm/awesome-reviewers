Verification API

Fetch method records, pinned source evidence and scan coverage as static JSON or Markdown. These endpoints describe inspected repository snapshots. They do not report execution results.

Endpoints

ResourcePath
Complete catalog and coverage/raw/verification/index.json
One method record/raw/verification/<id>.json
One method as Markdown/raw/verification/<id>.md
Repository scan manifest/raw/verification/repositories/<owner>--<repo>.json
Catalog overview/raw/verification/site.md
Text index/raw/verification/llms.txt
OpenAPI description/raw/verification/openapi.json

All endpoints are GET requests. Unknown paths return the host's HTML 404 page. Use the exact record identifiers and URLs supplied by the catalog.

Read the catalog

curl {{ site.url }}/raw/verification/index.json

Record fields

Each record contains a method, category, summary, named tools, recorded commands and evidence status. Source evidence includes a repository path, line range, excerpt and commit-pinned URL. Conditions, working directory and environment belong to the individual evidence item.

Repository manifests include the inspected commit, scan time, tree completeness, candidate and fetched file counts, skipped file counts and scan limitations. See the collection method for how to interpret these fields.

Legacy instruction endpoints

The original Awesome Reviewers API continues to serve the review-discussion instruction collection at its existing paths. Verification records use the separate /raw/verification/ prefix.
